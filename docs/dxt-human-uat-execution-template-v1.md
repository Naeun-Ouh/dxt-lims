# DXT Human UAT v1 — 실행 기록 양식

이 원본을 세션별로 복사하여 사용한다. 실제 사람이 수행하기 전에는 PASS/시간/클릭 수를 채우지 않는다. 30–60분 세션에서 아래 ‘실시간 기록 카드’를 과제마다 복사하고 자세한 이슈는 세션 후 정리한다.

참조: [시나리오·진행 가이드](dxt-human-uat-v1.md), [이슈 로그](dxt-human-uat-issue-log-v1.md).

- 참가자 익명 ID: ___ / Persona A·B·C: ___ / 관련 업무 경력: ___
- DXT 경험: 처음 / 이전 사용 ___ / Excel 사용 빈도: ___
- 예정 길이: 30 / 45 / 60분 / 실제 시작: ___ / 종료: ___
- 언어 순서: KO→EN / EN→KO / 모국어: ___
- 브라우저·viewport·배율: ___ / 화면 녹화·인용 동의: YES / NO
- Base URL: http://localhost:3200/ / 빌드·commit 또는 작업 상태 식별: ___
- 검증된 테스트 principal·접근 범위: ___ (Header 표시 이름만으로 추정하지 않음)
- 사용할 Study / Run / Subject / Dataset / Saved Analysis: ___
- 쓰기 허용: NO / YES — 대상 세션 Run·분석 이름·담당자 확인: ___
- 승인 입력 카드 위치·출처: ___ / 쓰기 전 기준값·exact refs 보관: ___
- Setup 자동저장 경로 회피 확인: [ ] / 필요한 상태·권한 사전 확인: [ ]
- 현재 준비되지 않은 과제와 이유: ___
- 오늘 실행 ID: ___ / 시간 부족 시 생략 ID: ___

쓰기 세션이면 생성된 Run 번호와 URL을 실제 응답 이후 적는다. 원본19/20/4/5/13/14를 전용 쓰기 대상으로 자동 간주하지 않는다. 별도 생성 원본, 승인 값, 완료/다음 차수 두 분기를 미리 정한다.

## 진행자가 처음 읽을 문장

“화면을 평가하는 시간이니 정답을 맞추려 하지 않으셔도 됩니다. 평소 방식으로 해보시고 생각나는 질문을 말해주세요. 제가 버튼 위치를 바로 알려드리지는 않겠습니다. 오늘 지정한 범위 밖의 저장이나 권한 변경은 하지 않습니다. 막히면 언제든 말씀해주세요.”

## 45분 진행 메모

- 0–4: 소개·동의·사전조건
- 4–11: HU-01/02/03
- 11–15: HU-06
- 15–23: HU-07/09/13/16
- 23–31: HU-17/19/20
- 31–37: HU-22/23/25
- 37–42: HU-26/27 + 반대 언어 핵심 경로
- 42–45: 회고

위 순서는 표준 안이다. 과제를 합쳐 수행해도 ID별로 결과를 기록한다. HU-31/32 전체를 축약했으면 PARTIAL 범위를 적고 전체 PASS로 세지 않는다. 30분안/페르소나별 대체안/쓰기60분안은 본문 가이드를 따른다.

## 실시간 기록 카드 — 과제마다 복사

### Session ___ / Scenario HU-___

- Persona: ___ / Locale: ___ / 실행한 하위 범위: 전체 / 일부 ___
- Readiness: READY / SAFE_LOCAL_INTERACTION / WRITE_REQUIRED / ROLE_REQUIRED / STATE_REQUIRED
- 시작 URL·선택 대상: ___ / 사전조건 충족: YES / NO ___
- 읽어준 User task: ___
- Expected observable result (진행자 전용): ___
- 시작 시각: ___ / 종료 시각: ___ / 총 소요 초: ___ / 그중 로딩·시스템 대기 초: ___
- 총 클릭: ___ / 잘못된 클릭: ___ / 키보드 이동·입력: ___ / 스크롤 횟수·방향: ___
- **도움 없이 완료? YES / NO / NOT ATTEMPTED**
- 도움: 없음 / L1 목표 재진술 / L2 영역 힌트 / L3 구체 조작·직접 URL
- 도움을 준 시각·정확한 말: ___
- Actual observable result: ___
- 결과: NOT_RUN / PASS / ASSISTED / FAIL / BLOCKED
- 완료 시 저장 여부: 없음 / 임시 초안만 / 영속 저장 ___
- 재조회 확인: NOT APPLICABLE / 일치 / 불일치 / 확인 못함
- Evidence: 화면/영상 타임코드·URL·선택값·exact refs ___
- Issue ID / Severity: ___ / P0·P1·P2·ENHANCEMENT·분류 전

짧은 관찰 항목은 ‘없음’ 또는 실제 인용/시각을 적는다. 공란은 미관찰이며 문제 없음으로 해석하지 않는다.

- **Hesitation points:** ___
- **Terminology questions:** ___
- **Navigation confusion:** ___
- **Excessive scrolling:** ___
- **Toolbar confusion:** ___
- **Inspector confusion:** ___
- **Grid interaction issues:** ___
- **Language issues:** ___
- **Excel fallback comment:** ___ (돌아가려던 단계·이유·필요한 작업)
- **Free-form user comment:** “___”
- 출처를 이해한다는 자신감1–5: ___ / 진행자 해석과 사용자 발언 구분: ___

클릭 계산: 버튼/셀/선택 항목 활성화마다1; native 메뉴 펼치기와 선택은 각각 기록. 키 입력과 스크롤은 클릭에 섞지 않는다. 잘못된 클릭도 총 클릭에 포함한다. 참가자의 생각 시간은 소요 시간에 포함한다. 네트워크 대기/도움 시간은 따로 남기며 임의로 빼서 빠르게 보이게 하지 않는다.

PASS는 사전조건 아래 요청 범위를 정확히 완료하고 의미를 설명한 경우에만 사용한다. ASSISTED는 완료했지만 도움을 받은 경우. BLOCKED는 데이터/권한/기능 전제 미충족이며 분모에서 분리한다. 단순히 facilitator가 대신 실행한 것은 완료가 아니다. NO 도움 없이 완료와 NOT_RUN을 같은 값으로 묶지 않는다.

## 세션 회고 (3–5분)

1. “이 결과가 어디에서 왔는지 얼마나 자신 있게 설명할 수 있나요?” 점수1–5와 이유: ___
2. “Excel로 돌아가고 싶었던 정확한 순간은 언제였나요?” ___
3. “오늘 가장 혼란스러웠던 말이나 버튼 세 가지는 무엇인가요?” ___
4. “다음 실험에도 스스로 사용할 수 있겠나요? 어떤 도움이 필요한가요?” ___
5. “한국어/영어 중 어느 쪽이 더 명확했고 어떤 단어가 어려웠나요?” ___

- 계획 과제 ___ = PASS ___ + ASSISTED ___ + FAIL ___ + BLOCKED ___ + NOT_RUN ___
- 시도 과제 분모 ___ = PASS + ASSISTED + FAIL (부분 실행은 별도 표기)
- Unassisted 완료 ___ / 시도 ___; assisted 완료 ___ / 시도 ___

- 고유 이슈 P0 ___ / P1 ___ / P2 ___ / ENHANCEMENT ___ (중복 제외)
- 환경/기능 사전조건 공백: ___ / 참가자 발언에 근거한 발견: ___
- 반복 이슈와 증거: ___ / 다음 재검증: ___ / 담당자: ___
- 남아 있는 임시 초안: ___ / 원본값 재확인: ___ / 생성한 세션 기록 보관 위치: ___
- 결정: 관찰 라운드 종료 / 추가 세션 필요 / 특정 흐름 중단 / 수용 검토 요청

P0 또는 필수 과제 보류가 남으면 전체 수용 완료를 체크하지 않는다. 실험 기록 삭제나 권한 변경으로 세션을 초기화하지 않는다.
